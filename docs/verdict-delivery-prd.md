# Rack Mesh — 판정 전달 PRD

작성일: 2026-09-10
개정: v0.1 (초안)
상위 문서: `infra-simulator-prd.md` v0.5, `prd-v0.6.md`
선행 문서: `display-layer-improvement-prd.md` v0.1
상태: 초안 (Draft)
작성 배경: engine 3.0.0 빌드(`Dual fabric API cluster` 시나리오)를 실행 상태에서 재검토한 결과

---

## 1. 한 줄 정의

엔진은 도메인 단위 단절까지 판정한다. 화면은 그 판정을 첫 화면에서 말하지 않는다. 이 문서는 **이미 계산된 판정이 사용자에게 도달하는 경로**를 고친다.

## 2. 배경

표시 계층 개선 PRD가 P0로 지목한 세 항목은 해결됐다. 실행 상태에서 확인한 내용은 다음과 같다.

| 항목 | 상태 | 확인 내용 |
|---|---|---|
| 5.1 손실 표기 분리 | 해결 | `무경로 미전달`과 `용량 드롭`이 별도 타일로 분리됨 |
| 5.2 백분율·부하 산술 일치 | 해결 | `FW A` 6회 샘플링에서 값이 고정이고 표시 백분율이 모두 `부하 / 한계`와 일치 |
| 5.3 상태 칩 공존 | 해결 | `EVIDENCE 4 UNKNOWN`과 `CAPACITY WARNING · 3`이 동시 표시됨 |
| 6.4 여유 배수 타일 | 해결 | `여유 배수 1.16×` 타일 도입. 단 부제 표기는 4.2에서 개정 |

도메인 단위 N-1과 N-2 스윕, 단일 장애 최악 사용률도 구현됐다. 계산은 정확하다. 등록된 도메인이 있으면 판정이 나오고, 이중화 무효 조건도 실제로 발화한다.

문제는 **기본 시나리오의 장애 도메인이 0개**라는 데 있다. 그래서 첫 화면에서 두 기능은 이렇게 보인다.

```
도메인 N-1        조건에 맞는 항목이 없습니다.
도메인 N-2        장애 도메인이 없어 이중 장애를 계산할 수 없습니다.
```

계산 능력이 늘어난 만큼 빈자리도 같이 늘었다. 6.1이 미해결로 남는 동안 장애 분석 범위 선택지에 `도메인 N-1`과 `도메인 N-2`가 새로 노출됐기 때문이다. 지금 이 제품은 자기가 가진 것 중 가장 차별적인 기능 두 개를 이름만 걸어두고 아무것도 보여주지 않는다.

두 번째 문제는 도메인을 등록해도 그 판정이 위로 올라오지 않는다는 것이다. 도메인 3개를 등록해 도메인 N-1에 단절 1건, N-2에 단절 3건이 나온 상태에서도 요약 타일은 `단일 장애점 04`를 유지한다. 캔버스 하단 서술은 해당 도메인을 정확히 지목하는데, 같은 화면의 요약은 그것을 모른다.

## 3. 목표

- 편집 없이 기본 시나리오만으로 도메인 단위 판정에 도달한다.
- 엔진이 내린 단절 판정이 요약 타일까지 올라온다. 어떤 층도 다른 층보다 안전하게 말하지 않는다.
- 화면에 내부 식별자가 나타나지 않는다.
- 화면 문구가 성립하지 않는 수치 표현을 쓰지 않는다.

### 비목표

- **AI 기능 도입.** 자연어 입력, 추천, 요약 생성, 한계 추정 어느 것도 이 문서의 범위가 아니다. 계산 경로와 한계 추정 경로에서 추론 모델을 배제한 기준 PRD의 판단을 그대로 유지한다.
- 계산 엔진 변경. 이 문서의 모든 항목은 기본 시나리오 데이터와 표시 계층에서 해결된다.
- 새 요약 타일 추가. 타일 예산은 6절에서 유지한다.
- 새 다이어그램 편집 기능. 기준 PRD 12절을 따른다.

## 4. 이 문서가 개정하는 결정

`README.md`의 변경 원칙에 따라, 선행 문서의 결정을 바꾸는 항목을 조용히 다르게 쓰지 않고 여기에 명시한다.

### 4.1 표시 계층 개선 PRD 6.1의 도메인 구성을 교체한다

6.1은 기본 시나리오에 넣을 장애 도메인으로 `RACK 04 = { LEAF A, API 01 }`, `RACK 07 = { LEAF B, API 02 }`를 처방했다. **이 구성은 6.1이 목표한 교훈을 가르치지 못한다.**

자원 단위 N-1 판정을 보면 이유가 분명하다.

| 자원 | 자원 N-1 판정 |
|---|---|
| LEAF A | 끄면 서비스 단절 |
| API 01 | 출발지·목적지 · 끄면 끊김 |

`RACK 04`의 두 구성원이 각각 이미 단절이다. 묶어도 자원 단위 스윕이 이미 말한 사실을 반복할 뿐이고, 도메인 단위 스윕이 자원 단위 스윕보다 무엇을 더 아는지는 끝내 드러나지 않는다. 6.1이 적은 목표("이 이중화는 실은 이중화가 아니다")를 그 처방이 달성하지 못한다.

**교체 처방: `PDU-3` = { SPINE A, SPINE B }, 종류 `전원`.**

| 대상 | 판정 |
|---|---|
| SPINE A 단독 | 끄면 82%만 전달 |
| SPINE B 단독 | 끄면 98%만 전달 |
| `PDU-3` (둘 다) | **끄면 서비스 단절** |

구성원 어느 쪽도 단일 장애점이 아니다. 둘을 같은 전원에 묶는 순간 단절이다. 이것이 도메인 단위 스윕이 존재하는 이유이며, `README.md`가 정의한 이중화 무효 조건(단절 또는 구성원 단독 최악보다 최소 전달률이 절대 5%p 이상 낮음)을 만족하는 이 토폴로지의 유일한 구성이다.

이 구성은 현실적이기도 하다. 스파인 두 대를 같은 랙 같은 PDU에 올리는 것은 흔하고, draw.io는 그 둘을 나란히 그려 이중화처럼 보이게 만든다. 우위가 가장 선명한 지점이다.

검증 결과 규칙은 이미 동작한다. `PDU-3`를 등록하면 캔버스 하단 서술이 스스로 `이중화 무효 도메인 실험`으로 바뀌고 실험 CTA가 붙는다. 판정 로직도, 서술 로직도 있다. 데이터만 없었다.

`RACK 04`와 `RACK 07`은 삭제하지 않고 함께 유지한다. 도메인 제안 목록이 두 랙을 제안하고 있고 5.3의 랙 예산과 짝이 맞는다. 다만 **교훈을 지는 도메인은 `PDU-3`이며, 기본 시나리오가 처음 가리켜야 할 대상도 그것이다.**

### 4.2 표시 계층 개선 PRD 6.4의 타일 부제 표기를 교체한다

6.4는 여유 배수 타일의 부제로 `1.16× 까지 · 다음 병목 leaf-b-api-b BPS`를 처방했고 빌드가 그대로 구현했다. 내부 식별자가 화면에 그대로 나온다. 처방 자체가 식별자를 담고 있었으므로 구현이 아니라 문서를 고친다. 7절이 정하는 표시명 규칙을 따른다.

## 5. P0 — 기본 시나리오가 판정 능력을 보여주지 않는다

### 5.1 장애 도메인을 채운다

**현상.** `분석 → 검증 설정`이 `서비스 0`, `장애 도메인 0`, `랙 0`, `시나리오 0`. 도메인 N-1과 N-2 섹션이 빈 상태 문구만 표시한다.

**요구사항.** `Dual fabric API cluster` 시나리오에 장애 도메인 세 개를 포함한다.

| 이름 | 종류 | 구성원 | 기대 판정 |
|---|---|---|---|
| `PDU-3` | 전원 | SPINE A, SPINE B | 끄면 서비스 단절 · 이중화 무효 |
| `RACK 04` | 공간 | LEAF A, API 01 | 끄면 서비스 단절 |
| `RACK 07` | 공간 | LEAF B, API 02 | 끄면 서비스 단절 |

도메인 세 개면 N-2 조합이 3건 생기므로 N-2 섹션도 빈 상태를 벗어난다.

**인수 기준.** 첫 로드에서 편집 없이 장애 주입 패널을 열면 도메인 N-1에 항목 3개, 도메인 N-2에 조합 3개가 보인다. 도메인 N-1 항목 중 최소 하나가 이중화 무효로 표시된다.

### 5.2 서비스 수용 기준을 채운다

**현상.** 서비스 0개. 판정 도구가 판정 기준 없이 시작한다. 통과 보류 상태는 근거 미확인만으로 결정되고, 전달률이 얼마여야 하는지는 아무도 말하지 않는다.

**요구사항.** 서비스 `Public API`, 최소 전달률 99%, 검증할 수요 `Public API` 연결.

**왜 99%인가.** 이 시나리오에서 세 결과가 모두 도달 가능해진다. 정상 상태 100%는 통과, `EDGE A` 단독 장애의 82%는 불합격, `PDU-3` 도메인 장애의 단절은 완전 실패다. 기준 하나로 판정의 세 단계가 다 드러난다. 100%로 두면 정상 상태만 겨우 통과하고 단일 장애와 도메인 장애가 같은 등급으로 뭉개진다.

**인수 기준.** 서비스 탭이 `서비스 1`. 장애 없는 상태에서 `Public API`가 통과. `EDGE A` 주입 시 불합격.

### 5.3 랙 예산을 채운다

**현상.** 랙 0개. 대역폭이 아닌 축이 먼저 병목이 되는 사례에 도달할 수 없다. 다축 제약을 말하는 도구가 전력과 U를 한 번도 보여주지 않는다.

**요구사항.** `RACK 04`에 전력 예산(W)과 공간(U)을 넣는다. 전력 기준은 `명판값`으로 둔다.

**주의.** 전력과 U 값은 합성값이다. 표시 계층 개선 PRD 7.2의 합성값 표시 규칙 적용 대상이며, 내보내기에도 합성 표시가 따라가야 한다.

**인수 기준.** 랙 탭이 `랙 1`이고 랙 수용량 판정이 계산된다.

## 6. P1 — 요약이 도메인 판정을 흡수하지 않는다

**현상.** 도메인 3개를 등록해 도메인 N-1에 단절 1건, 도메인 N-2에 단절 3건이 나온 상태에서 요약 타일은 `단일 장애점 04`를 그대로 유지한다. 캔버스 하단 서술은 해당 도메인을 지목하지만 요약은 모른다.

**원인.** `단일 장애점` 타일이 자원 단위 스윕 결과만 읽는다. 도메인 단위 결과는 사이드바 안쪽에만 있다.

**왜 중요한가.** 표시 계층 개선 PRD 5.3이 이미 같은 원칙을 정했다. 직교하는 두 상태가 한 슬롯을 나눠 쓰면 하나가 다른 하나를 지운다. 자원 단위 SPOF와 도메인 단위 단절도 직교한다. **자원 SPOF가 0개인데 도메인 단절이 존재하는 설계가 가능하고, 그것이 정확히 이 제품이 잡아내려는 설계다.** 그 상태에서 요약이 `단일 장애점 0`을 보이면 화면이 거짓을 말한다. 5.1이 손실을 0으로 보고하던 것과 같은 형태의 결함이다.

또한 심사자나 처음 보는 사용자는 사이드바 아래까지 내려가지 않는다. 요약 타일이 도달 경로의 전부다.

**요구사항.** 새 타일을 만들지 않는다. 표시 계층 개선 PRD 4.1의 불변 조건 3(집계값은 떨지 않는다)과 타일 예산 유지를 지키면서, `단일 장애점` 타일이 두 층을 함께 말한다.

- 도메인 단절 0건: 현행 유지.
- 도메인 단절 1건 이상: 값에 도메인 건수를 병기하고 부제가 최악 도메인을 지목한다. 예) 값 `4 + 도메인 1`, 부제 `PDU-3 · 이중화 무효`.
- 자원 SPOF 0건이고 도메인 단절 1건 이상: **값에 `0`을 표시하지 않는다.** 이 상태에서 0은 거짓이다.

**인수 기준.** 자원 SPOF가 0이고 도메인 단절이 1 이상인 토폴로지에서 요약 타일이 안전을 보고하지 않는다. 요약 타일이 지목하는 최악 대상과 캔버스 하단 서술이 지목하는 대상이 일치한다.

## 7. P2 — 표시명과 식별자

### 7.1 내부 식별자가 화면에 노출된다

**현상.** 세 곳에서 내부 식별자가 그대로 보인다.

| 위치 | 현재 | 기대 |
|---|---|---|
| 최소 headroom 타일 부제 | `leaf-b-api-b · BPS` | `LEAF B → API 02 · BPS` |
| 도메인·랙 폼의 링크 체크박스 | `edge-a-fw-a` | `EDGE A → FW A` |
| 도메인 N-2 결과 라벨 | `feed-a + pdu-3` | `FEED A + PDU-3` |

도메인 폼 안에서 장비는 표시명(`EDGE A`), 링크는 식별자(`edge-a-fw-a`)로 갈린다. 한 폼에 두 명명 체계가 공존한다. 장애 목록은 같은 링크를 `EDGE A → FW A`로 이미 잘 부르고 있으므로 표시명 자체는 존재한다. 일부 지점이 그것을 쓰지 않을 뿐이다.

**요구사항.** 링크 표시명을 `{출발 장비} → {도착 장비}`로 만드는 함수를 하나 두고 모든 표시 지점이 그것을 쓴다. 식별자는 저장 파일, 내보내기 데이터, DOM 속성에만 남는다.

**인수 기준.** 렌더된 화면 텍스트에 소문자 하이픈 식별자가 나타나지 않는다.

### 7.2 기본 시나리오의 식별자와 표시명이 어긋난다

**현상.** 링크 식별자가 `leaf-b-api-b`인데 대상 서버의 표시명은 `API 02`다. `api-b`와 `API 02`가 같은 장비다.

**요구사항.** 기본 시나리오 데이터에서 식별자와 표시명의 명명 규칙을 하나로 맞춘다. 식별자를 표시명에 맞추거나(`leaf-b-api-02`) 표시명을 식별자에 맞춘다(`API B`).

**왜 중요한가.** 7.1을 고치면 화면에서는 보이지 않는다. 그러나 저장 파일과 내보내기 데이터를 사람이 읽는 순간 다시 나타나고, 그때는 같은 장비를 두 이름으로 부르는 데이터로 보인다. 기준 PRD 8절이 요구하는 인용 가능성과 어긋난다.

### 7.3 자원명 표기가 흔들린다

**현상.** 여유 배수 타일 부제는 `최악 LEAF-A`(하이픈), 나머지 모든 지점은 `LEAF A`(공백).

**요구사항.** 자원명은 어느 지점에서도 변형하지 않는다. 대문자화, 하이픈 치환, 공백 제거를 표시 계층에서 하지 않는다.

## 8. P3 — 문구와 수치 위생

### 8.1 성립하지 않는 수치 표현

**현상.** `생존 0.00× 이하`.

배수는 0 미만이 없으므로 `0.00× 이하`는 정보를 담지 않는다. 실제 뜻은 최악 단일 장애에서 정상 트래픽조차 전달하지 못한다는 것이다.

**요구사항.**

- 생존 배수가 0이면 `생존 불가`로 적는다.
- 0보다 크면 값을 그대로 적는다. `생존 0.82×`.
- `이하`는 스윕이 상한만 아는 축이 포함됐을 때만 붙인다. 값이 확정된 경우에 습관적으로 붙이지 않는다.

`이하`의 용법은 장애 목록의 `171% 이하`와 같은 의미여야 한다. 두 곳이 같은 접미사를 다른 뜻으로 쓰면 안 된다.

### 8.2 자릿수 채움

**현상.** `과부하 자원 00`, `무경로 미전달 00`.

**요구사항.** 값 앞을 0으로 채우지 않는다. `0`과 `00`이 다른 뜻처럼 읽힌다. 자리 맞춤이 필요하면 레이아웃으로 해결한다.

### 8.3 값과 부제가 같은 사실을 말한다

**현상.** `무경로 미전달` 타일이 값 `00`, 부제 `0 Mbps 미전달`. 같은 말이 두 번이다.

**요구사항.** 부제는 값이 말하지 않는 사실을 말한다. 무경로 수요가 없으면 `무경로 수요 없음`처럼 상태의 이유를 적는다.

### 8.4 조사가 자원명 받침을 따르지 않는다

**현상.** `PDU-3 스파인 공용를 끄면 어떻게 될까요?`. 받침이 있으므로 `공용을`이 맞다.

**요구사항.** 받침에 따라 을/를, 이/가, 은/는, 와/과를 고르는 함수를 두고 자원명을 문장에 넣는 모든 지점이 쓴다. 자원명은 사용자가 입력하므로 문구에 하드코딩할 수 없다. 영문과 숫자로 끝나는 이름도 처리한다.

### 8.5 여유 배수 타일 부제가 과밀하다

**현상.** `다음 병목 LEAF B → API 02 · BPS · 단절 · 생존 0.00× 이하 · 최악 LEAF-A · 끝점 4개 제외`. 사실 6개가 한 줄이다. `끝점 4개 제외`는 무엇이 왜 제외됐는지 알 수 없다.

**요구사항.** 부제는 사실 2개까지 담는다. 병목과 생존만 남긴다. 나머지는 장애 패널이 이미 더 자세히 말한다. `끝점 N개 제외`를 유지하려면 제외 이유를 툴팁으로 붙인다. 이유를 붙일 수 없으면 뺀다.

### 8.6 접근명에 이름이 빠진다

**현상.** 도메인 목록 항목의 접근명이 `· 전원 · 자원 3개 삭제`로 시작한다. 도메인 이름이 빠져 있다.

**요구사항.** 목록 항목의 접근명이 표시된 이름으로 시작한다.

## 9. 소유자가 다른 항목

다음은 이 문서가 정하지 않는다. 재검토에서 확인한 미해결 상태만 기록한다.

- **편집 툴바가 요약보다 위에 있다.** 소유자는 표시 계층 개선 PRD 6.3. 미해결. 최초 로드에서 툴바 7개가 전부 비활성이고 첫 화면에서 가장 넓은 줄이 회색이다. 5.1이 도메인을 채우고 6절이 요약을 고치면 이 줄 아래로 밀리는 정보의 가치가 더 커지므로 6.3의 우선순위를 재평가할 근거가 생긴다.
- **스윕 결과의 화면 배치.** 소유자는 `fault-sweep-surfacing-prd.md`.
- **합성값 표시.** 소유자는 표시 계층 개선 PRD 7.2. 부분 해결. 노드에 `SYN` 배지가 붙었고 캔버스에 `SYNTHETIC TOPOLOGY` 워터마크가 생겼다. 제조사명과 합성 모델명을 함께 찍는 형태(`Fortinet DEMO-FW-42K`)는 남아 있다.

## 10. 검증 전략

기준 PRD 9절의 회귀 테스트에 다음을 추가한다.

**기본 시나리오 무결성.** 첫 로드에서 서비스 1개 이상, 장애 도메인 3개 이상, 랙 1개 이상이 존재한다.

**도메인 우위.** 기본 시나리오에 구성원 단독 최악보다 최소 전달률이 5%p 이상 낮은 도메인이 최소 하나 존재한다. 이 테스트가 4.1의 교체 근거를 고정한다. 나중에 누가 도메인 구성을 되돌리면 이 테스트가 먼저 깨진다.

**식별자 비노출.** 렌더된 화면 텍스트에 소문자 하이픈 식별자 패턴이 나타나지 않는다. 저장 파일과 내보내기 데이터는 대상에서 제외한다.

**요약 정합.** 도메인 단절이 1건 이상인 모든 주입 조합에서 `단일 장애점` 타일이 `0`을 표시하지 않는다. 요약이 지목하는 최악 대상과 하단 서술이 지목하는 대상이 같다.

**조사 처리.** 받침 있는 이름, 받침 없는 이름, 숫자로 끝나는 이름, 영문으로 끝나는 이름 각각에 대해 문장이 올바른 조사를 고른다.
