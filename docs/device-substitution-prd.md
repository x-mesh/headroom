## 1. 한 줄 정의

토폴로지의 한 자리에 다른 장비 모델을 끼워 넣고 다시 계산해서, **무엇으로 바꾸면 병목이 어디로 옮겨 가는지**를 보여준다. 진단에서 처방으로 넘어가는 한 걸음이다.

## 2. 배경

지금 제품은 `FW B 의 신규 세션이 한계를 넘었습니다. 72 Kcps / 42 Kcps 로 171% 입니다`까지 말하고 멈춘다. 실무자가 그다음에 하는 일은 벤더 데이터시트를 뒤지고 스프레드시트를 만드는 것이다. 그 작업이 이 도구 밖에서 일어나고, 거기서 조건이 섞이고 단위가 틀린다.

필요한 것은 이미 다 있다. 카탈로그에 실제 모델이 들어 있고(방화벽 기준 `Fortinet FortiGate 100F / 1000F / 1800F`, `Palo Alto Networks PA-3410 / PA-3440`, `Cisco Secure Firewall 3105 / 3140`), 엔진은 결정적이며, 축별 근거와 조건 적용 가능성 판정(`evidenceApplicability`)도 있다. 장비를 갈아 끼우고 다시 계산하는 비용은 재계산 한 번이다.

목표 출력은 이런 문장이다.

> `FW A` / `FW B` 를 `PA-3440` 으로 바꾸면 생존 배수가 0.71 → 1.9 가 됩니다. 병목이 `FW B · CPS` 에서 `SPINE B · BPS` 로 옮겨 갑니다.

이 순간 도구의 성격이 바뀐다. 설계 검토 도구에서 구매 검토 도구가 된다. 예산이 움직이는 자리로 올라가고, 그림 도구는 근처에도 오지 못한다.

## 3. 벤더 데이터 취급 원칙과의 관계

이 기능은 상위 PRD 8절의 금지선에 가장 가까이 간다. 먼저 경계를 정한다.

### 3.1 8절이 금지한 것

8절 원문은 벤더 간 순위나 우열 비교 화면을 만들지 않는다고 정하고, 같은 문단에서 다음을 명시한다.

> 사용자가 자기 토폴로지 안에서 두 장비를 바꿔가며 비교하는 건 자연스럽지만, 도구가 정규화된 벤더 랭킹을 산출하지는 않는다.

즉 금지 대상은 **정규화된 랭킹**이고, 토폴로지 안의 치환 비교는 상위 PRD가 이미 자연스러운 것으로 본다. 이 기능은 후자에 속한다.

### 3.2 판정 규칙

| | 허용 | 금지 |
|---|---|---|
| 기준점 | 사용자가 지정한 **자리**에서의 결과 | 자리와 무관한 모델 자체의 점수 |
| 종속성 | 이 토폴로지, 이 수요, 이 워크로드 조건에 종속 | 조건을 제거한 정규화 값 |
| 집계 | 모델 단위 | 벤더 단위 |
| 표현 | 계산 결과 문장 | `권장`, `최고`, `우수` 같은 도구의 평가어 |
| 재배포 | 내 설계의 단일 상태 | 후보 비교표의 공유·내보내기 |

핵심은 **숫자가 토폴로지를 떠나면 안 된다**는 것이다. `PA-3440 이 이 자리에서 1.9배`는 내 설계에 대한 사실이고, `PA-3440 은 1.9배`는 벤더 주장이 된다.

### 3.3 경계 사례 판정

| 사례 | 판정 | 근거 |
|---|---|---|
| 인스펙터에서 현재 장비와 후보 하나를 비교 | 허용 | 8절이 명시적으로 자연스럽다고 본 경우 |
| 후보 7종을 표로 세우고 `교체 후 생존 배수` 열로 정렬 | 조건부 허용 | 토폴로지 종속이라 정규화 랭킹이 아니다. 단 상시 고지와 내보내기 금지를 붙인다(3.4) |
| `CPS 기준 상위 모델` 같은 토폴로지 무관 목록 | 금지 | 자리와 무관한 모델 순위다 |
| 벤더별 집계 (예: 제조사 평균 비교) | 금지 | 모델 단위를 벗어난 벤더 단위 집계다 |
| 같은 벤더 내 상위 모델 제안 (`100F` → `1000F`) | 허용 | 벤더 간 비교가 아니다 |
| 사용자가 후보 목록을 한 벤더로 필터 | 허용 | 사용자의 선택이고 도구의 판단이 아니다 |
| 도구가 후보에 `권장` 배지를 붙임 | 금지 | 평가어는 정규화된 판단이다. 계산 결과 문장으로만 말한다 |
| 후보 비교표를 PNG로 내보내기 | 금지 | 표가 토폴로지를 떠나면 랭킹으로 읽힌다 |
| 치환을 적용한 설계를 SVG로 내보내기 | 허용 | 내 설계의 한 상태이고 기존 내보내기와 같다 |

### 3.4 조건부 허용에 붙는 제약

후보를 여럿 나란히 보이는 화면에는 다음을 모두 붙인다.

- 상시 고지. `이 값은 현재 설계와 워크로드 조건에서만 유효합니다. 장비 성능 비교가 아닙니다.` 접히거나 스크롤로 사라지지 않는 자리에 둔다.
- 내보내기 차단. 이 화면은 SVG, PNG, 클립보드 복사 대상이 아니다.
- 출처 표기. 각 후보 행에 `source.type`과 조건 요약을 붙인다. 숫자만 남는 행을 만들지 않는다.
- 평가어 금지. 정렬은 하되 `1위`, `권장` 같은 라벨을 쓰지 않는다.

## 4. 목표와 비목표

### 목표

- 토폴로지의 한 자리를 다른 모델로 바꾼 결과를 비파괴로 미리 본다.
- 병목이 어디로 옮겨 가는지를 첫 번째 출력으로 낸다.
- 치환 후보의 근거가 현재 워크로드 조건과 맞지 않으면 숫자를 내놓지 않는다.
- 같은 역할의 장비를 묶어 함께 교체할 수 있다.

### 비목표

- 가격, 납기, 라이선스, 지원 계약. 견적은 지역과 시점과 계약 조건에 따라 달라지고 출처를 고정할 수 없다. 상위 PRD는 조건 없는 숫자를 거부하므로 이 값들은 같은 원칙에 의해 제외된다.
- 벤더 랭킹. 3절에서 정한 금지선을 넘지 않는다.
- 구성 생성. Ansible이나 장비 config를 만들지 않는다. 상위 PRD 3절 비목표다.
- 토폴로지 변경 제안. 장비를 추가하거나 링크를 새로 잇는 처방은 이 문서의 범위가 아니다. 같은 자리의 모델 교체만 다룬다.

전력과 U는 **포함한다.** 이미 장비 모델에 있고 `topology.racks`의 전력 예산과 U 공간 검증에 직접 연결된다. 방화벽을 키웠더니 랙 전력 예산을 넘는 경우는 이 도구가 잡아야 하는 대표적 사례다.

## 5. 개념 모델

### 5.1 자리(slot)

치환의 단위는 장비 객체가 아니라 **자리**다. 자리는 토폴로지에서 같은 역할을 하는 장비 하나 또는 여럿이다. 자리를 구성하는 기준은 다음을 모두 만족하는 것으로 제안한다. 최종 기준은 미결이다.

- 같은 `kind`
- 같은 `spec.catalogId` (직접 입력 장비는 같은 모델 문자열)
- 링크 연결 패턴이 대칭

실무에서 방화벽은 쌍으로 바꾼다. 한 대만 바꾸면 비대칭 용량이 생겨 설계가 더 나빠질 수 있고, 그 상태를 기본값으로 보여주면 오해를 만든다. 그래서 자리 개념이 필요하다.

UI는 기본으로 자리 전체를 선택하고, 한 대만 바꾸는 것도 허용한다. 한 대만 바꾸면 비대칭이 생긴다는 사실을 문장으로 알린다.

### 5.2 비파괴 미리보기

치환은 기본적으로 설계를 바꾸지 않는다. 미리보기 상태에서 결과를 계산해 보여주고, 사용자가 적용하면 그때 설계가 바뀐다.

기준선 비교(`설계 변화` 패널)를 재사용하지 않는다. 기준선은 설계를 불러온 시점에 고정되는 값이고, 치환 비교는 현재 설계 대비 비교다. 둘을 한 패널에 섞으면 어느 쪽 대비인지 알 수 없다. 치환 결과는 별도 자리에 `현재 → 치환 후` 형식으로 낸다.

적용하면 기존 `historyStep` 경로에 기록되어 되돌리기가 동작한다.

### 5.3 조건 적용 가능성이 계산을 막는다

후보 모델의 근거에는 측정 조건이 붙어 있다. `evidenceApplicability(record, workloadConditions, workloadScope)`가 현재 워크로드 조건과 비교해 맞지 않으면 해당 축을 `status: 'unknown'`으로 바꾸고 `unknownReason`을 `evidence-incompatible` 또는 `evidence-applicability-unknown`으로 남긴다.

이 경우 `교체하면 1.9배`를 말할 수 없다. 조건이 다른 숫자로 계산한 배수는 근거가 없다.

출력은 숫자가 아니라 판정과 다음 행동이다.

> `PA-3440` 의 신규 세션 근거는 `features_enabled: []` 조건에서 측정되었습니다. 현재 워크로드는 `ips`, `logging` 을 켠 조건입니다. 이 축으로는 배수를 계산할 수 없습니다.
> 조건 불일치를 수락하고 계산하거나, 같은 조건의 근거를 임포트하십시오.

수락 경로는 기존 것을 쓴다. `acceptanceDigest(record, workloadConditions, workloadScope)`로 봉인하고 `user-asserted`로 인정한다. 수락해서 계산한 결과에는 그 표시가 끝까지 따라붙는다.

## 6. 기능 요구사항

### 6.1 자리 선택과 후보 지정

장비를 선택하면 그 장비가 속한 자리를 보이고, 자리 전체 또는 한 대를 치환 대상으로 고를 수 있다. 후보는 같은 `kind`의 카탈로그 항목에서 사용자가 고른다.

**인수 기준.** `FW A`를 선택하면 `FW A`와 `FW B`가 한 자리로 묶여 보이고, 자리 전체 치환이 기본 선택이다.

### 6.2 비파괴 미리보기와 적용

치환 미리보기는 설계를 바꾸지 않는다. 적용하면 설계가 바뀌고 되돌리기가 가능하다. 미리보기를 취소하면 아무 흔적이 남지 않는다.

**인수 기준.** 미리보기 후 취소하면 토폴로지 직렬화 결과가 미리보기 이전과 바이트 단위로 같다. 적용 후 되돌리기 한 번으로 원래 상태로 돌아온다.

### 6.3 병목 이동을 첫 출력으로 낸다

결과의 첫 줄은 배수가 아니라 병목의 이동이다. 방화벽을 키웠더니 스위치가 병목이 되는 상황을 먼저 보이는 것이 예산 낭비를 막는다.

출력 순서는 다음과 같다.

1. 병목 이동. `FW B · CPS 171%` → `SPINE B · BPS 94%`
2. 생존 배수 변화. `0.71× → 1.9×` (`docs/survival-multiplier-prd.md`의 지표)
3. 정상시 배수 변화. `1.16× → 2.4×`
4. 과부하 자원 수 변화
5. 전력과 U 변화. 랙 예산을 넘으면 경고

**인수 기준.** 치환 결과 화면의 첫 줄이 병목 이동이고, 병목이 같은 자원에 남아 있으면 `병목 그대로`를 명시한다.

### 6.4 조건 불일치 시 숫자를 내놓지 않는다

후보의 어떤 축이든 조건 적용 가능성 판정에서 `unknown`이 되면 그 축이 관여하는 지표를 숫자로 내지 않는다. 판정과 불일치 항목, 수락 경로를 보인다.

**인수 기준.** 워크로드 조건을 `security` 프리셋(`features_enabled: ['ips', 'application-control', 'logging']`)으로 두고 `features_enabled: []` 조건의 근거를 가진 후보를 고르면 배수가 표시되지 않고 불일치 항목이 열거된다.

### 6.5 자리를 부분 치환할 때의 경고

자리 안의 일부만 바꾸면 비대칭 용량이 생긴다. 그 사실을 문장으로 알리고, 비대칭 상태의 계산 결과는 정상적으로 낸다. 막지는 않는다. 단계적 교체는 실제 계획이다.

**인수 기준.** `FW A`만 치환하면 비대칭 경고가 보이고 결과는 계산된다.

### 6.6 후보 비교 화면의 제약

여러 후보를 나란히 보이는 화면에는 3.4절의 네 가지 제약을 모두 적용한다.

**인수 기준.** 후보 비교 화면에서 내보내기와 복사가 동작하지 않고, 고지 문구가 스크롤과 무관하게 보이며, 어떤 행에도 평가어 라벨이 없다.

### 6.7 출처 고지

치환 후 숫자는 데이터시트나 제3자 시험 근거에서 나온다. 실측이 아니다. 결과 화면에 근거 종류별 축 개수를 표시하고, 적용 후 내보내기에도 상위 PRD 8절이 요구하는 출처, 조건, 엔진 버전을 싣는다.

**인수 기준.** 치환 결과 화면에 `데이터시트 3축 · 추정 1축` 형태의 요약이 보인다. 적용 후 SVG 내보내기에 출처 고지가 포함된다.

## 7. 표시 요구사항

치환 결과는 집계값이므로 떨림 대상이 아니다. `docs/display-layer-improvement-prd.md` 4.1절 불변 조건 3을 따른다.

치환으로 들어온 값의 출처는 후보 모델의 `source.type`을 그대로 쓴다. 같은 문서 4절의 출처 게이트에 따라, 데이터시트 근거로 계산된 축은 좁게 흔들리고 실측 근거가 있으면 멈춘다. 치환은 출처를 새로 만들지 않는다.

## 8. 비기능 요구사항

| 항목 | 목표 |
|---|---|
| 미리보기 재계산 | 기존 재계산 예산 안. 치환은 한계값만 바꾸므로 토폴로지 재탐색이 필요 없을 것으로 추정. 확인 필요 |
| 비파괴 보장 | 미리보기 취소 후 직렬화 결과가 동일 |
| 결정성 | 같은 치환은 같은 결과 |
| 외부 요청 | 없음. 카탈로그는 번들 데이터다 |
| 내보내기 차단 | 후보 비교 화면은 내보내기와 복사 대상에서 제외 |

## 9. 검증 전략

**비파괴.** 미리보기 진입과 취소를 반복한 뒤 `serializeProject` 결과가 처음과 같다.

**적용과 되돌리기.** 적용 후 되돌리기 한 번으로 원래 상태가 되고, 다시하기로 치환 상태로 복귀한다.

**병목 이동 검출.** 치환 전후 병목 자원이 바뀌는 시나리오와 바뀌지 않는 시나리오 각각에서 출력 첫 줄이 올바르다.

**조건 게이트.** 조건이 맞지 않는 후보에서 배수가 숫자로 나오지 않는다. 수락 후에는 계산되고 `user-asserted` 표시가 결과에 남는다.

**자리 구성.** 대칭 쌍이 한 자리로 묶이고, `catalogId`가 다른 장비는 묶이지 않는다.

**금지선.** 후보 비교 화면에 내보내기 경로가 없고, 평가어 문자열이 코드에 존재하지 않는다. 금지어 목록을 테스트로 고정한다.

**전력과 U.** 치환으로 랙 전력 예산을 넘기면 경고가 발생한다.

## 10. 결정 사항과 미결 사항

### 결정됨 (v0.1)

**치환 단위는 자리이고 기본값은 자리 전체다.** 한 대만 바꾸는 것도 허용하되 비대칭을 알린다.

**비파괴 미리보기가 기본이다.** 기준선 비교와 섞지 않고 별도 자리에 `현재 → 치환 후`로 낸다.

**첫 출력은 병목 이동이다.** 배수보다 먼저 온다.

**조건이 맞지 않으면 숫자를 내놓지 않는다.** 기존 수락 경로를 재사용한다.

**가격, 납기, 라이선스는 비목표다.** 출처를 고정할 수 없는 숫자는 다루지 않는다. 전력과 U는 포함한다.

**후보 비교 화면은 조건부 허용이고 내보낼 수 없다.** 3.4절의 네 제약을 모두 적용한다.

**도구는 평가어를 쓰지 않는다.** `권장`, `최고`, `1위`를 금지어로 고정한다.

### 미결

**자리 구성 기준.** 5.1절의 세 조건이 충분한지. 링크 연결 패턴의 대칭을 판정하는 알고리즘이 필요하고, 복잡하면 사용자가 자리를 직접 묶는 방식으로 후퇴할 수 있다.

**후보 제안의 범위.** 사용자가 고르는 것만 할지, 도구가 후보를 추려 보일지. 추린다면 필터 기준을 현재 병목 축의 한계가 더 큰 모델로 한정하는 방안이 있으나, 추리는 행위 자체가 평가로 읽힐 위험이 있다.

**카탈로그 깊이.** 현재 방화벽은 7종이지만 스위치와 라우터, 서버의 후보가 충분한지 확인 필요. 카탈로그가 얇으면 이 기능이 방화벽에서만 쓸모가 있다.

**직접 입력 장비의 치환.** `직접 입력` 상태의 장비를 카탈로그 모델로 바꾸는 방향은 자연스럽다. 역방향은 의미가 불분명하다.

**수락한 조건 불일치의 전파.** 치환 미리보기에서 수락한 조건이 적용 후에도 유지되는지, 미리보기 범위에서만 유효한지 정해야 한다.

**자리 단위 전력 합산.** 자리 전체를 교체하면 전력과 U가 배수로 늘어난다. 랙 예산 검증이 자리 단위 변화를 어떻게 받을지 `topology.racks` 쪽과 함께 정한다.

## 11. 작업 순서

1. 비파괴 미리보기 기반. 치환된 한계값으로 엔진을 한 번 더 돌리고 결과를 따로 보관하는 구조.
2. 병목 이동 출력과 지표 4종.
3. 조건 적용 가능성 게이트와 수락 경로 연결.
4. 자리 구성. 단순 기준(같은 `kind` + 같은 `catalogId`)으로 먼저 내고 대칭 판정은 뒤로 미룬다.
5. 적용과 되돌리기 연결.
6. 전력과 U 변화. `topology.racks`에 항목이 생긴 뒤에 의미가 있다.
7. 후보 비교 화면과 3.4절 제약. 금지어 테스트를 먼저 넣는다.

## 12. 손대지 말 것

- 카탈로그 데이터 구조와 `device.spec` / `device.overrides` / `device.accepted`의 의미. 치환은 이 구조를 읽고 쓰는 것이지 바꾸는 것이 아니다.
- `evidenceApplicability`와 `acceptanceDigest`의 판정 로직.
- 상위 PRD 8절. 이 문서는 8절을 해석할 뿐 완화하지 않는다.
- 기준선 비교 패널의 의미. 치환 결과를 그 패널에 섞지 않는다.
