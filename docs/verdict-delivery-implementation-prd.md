# 판정 전달 PRD — 구현 준비 초안

작성일: 2026-09-10
상태: 정책 결정 대기. 구현 미승인.
기준: [원문 PRD](verdict-delivery-prd.md). 원문을 보존하고 현재 코드와 차이를 기록한다.

## 1. 제품 목표

기본 데모를 연 사용자가 편집 없이 공유 전원 장애의 위험을 발견하고 요약에서 같은 판정을 읽는다. 성공은 도메인 N-1 3건, N-2 3건, PDU-3 이중화 무효, 요약과 하단의 대표 대상 일치로 관찰한다.

## 2. 현재 확인한 상태

서비스는 1개, 장애 도메인은 2개, 랙은 3개다. PDU-3만 빠져 있다. 기존 객체를 다시 만들거나 기존 랙을 삭제하지 않는다.

메모리 복제본에 PDU-3를 추가하면 세 도메인이 모두 단절이고 N-2 세 조합도 모두 단절이다. 이중화 무효는 PDU-3 한 건이다. 요약의 도메인 단절 수는 3이며 이중화 무효 수 1과 구분한다.

정상 Public API는 통과 보류이고 EDGE A 장애는 실패다. 서버 NIC PPS 한계가 미확인이다. 정상 전달률이 100%로 표시되어도 확정 통과를 뜻하지 않는다. 99%와 100%라는 기준 선택만으로 실패와 완전 단절이라는 새 판정 등급이 생기지는 않는다.

## 3. 범위와 요구사항

### R1

기존 두 랙 도메인을 보존하고 PDU-3를 추가한다. N-1 3건, N-2 3건, 이중화 무효를 노출한다.

### R2

Public API 99% 기준을 유지한다. 정상 통과와 미확인 축 보존의 충돌은 Q1 결정 후 구현한다.

### R3

RACK 04 명판 전력과 U 판정을 제공하고 합성 표시를 화면과 내보내기에 보존한다.

### R4

기존 요약 타일에 자원 SPOF와 도메인 N-1 단절 건수를 구분하고 하단과 대표 대상을 통일한다.

### R5

링크·자원·도메인 조합의 표시명을 일관되게 사용하고 내부 ID를 화면에 노출하지 않는다.

### R6

기본 API 표시명과 ID를 정합화하되 기존 저장 파일의 참조를 보존한다.

### R7

생존 0, 상한 접미사, 앞자리 0, 중복 부제를 고치고 병목·생존 두 사실만 남긴다.

### R8

기존 조사 함수를 확장하고 도메인 목록 및 삭제 버튼의 접근명에 이름을 포함한다.

## 4. 표시 계약

도메인 건수는 N-1 단절만 센다. 자원 4개와 도메인 3개라면 “4 + 도메인 3”, 자원 0개와 도메인 1개라면 “도메인 1”로 표시한다. 도메인 단절이 없으면 기존 자원 요약을 유지한다.

대표 도메인은 단절 중 이중화 무효 우선, 최소 전달률 오름차순, ID 순으로 선택한다. 요약과 하단 실험이 이 선택을 함께 사용한다. 계산 중에는 완료 판정을 새 결과처럼 표시하지 않는다. 활성 장애 수를 표시할 때에도 도메인 단절 사실은 부제와 접근명에 남긴다.

링크는 출발 장비 이름 → 도착 장비 이름으로 표시한다. 도메인 조합은 도메인 표시명을 연결한다. 사용자 이름의 대소문자와 공백을 보존한다. 내부 ID 검사는 알려진 ID의 실제 노출을 대상으로 하며 하이픈이 든 사용자 이름을 금지하지 않는다.

여유 배수 부제는 병목과 생존 두 사실을 담는다. 생존 0은 “생존 불가”, 미확정은 “미확정”, 작은 양수는 0으로 오인하지 않는 정밀도로 표시한다. “이하”는 양수 상한에만 붙인다. 끝점 제외 문구는 요약에서 제거하는 안을 권고한다.

기존 조사 처리를 확장한다. 숫자는 한자음, 영문 마지막 글자는 알파벳 이름으로 읽는 규칙을 명시한다. 발음이 불명확한 이름은 이름을 유지하고 조사가 필요 없는 문장으로 표현한다.

## 5. 데이터와 호환성

PDU-3는 SPINE A/B를 함께 묶는다. RACK 04/07을 보존한다. 신규 기본 데모에만 적용하고 사용자가 저장한 프로젝트를 자동 변경하지 않는다.

RACK 04는 명판 기준으로 장비 값과 예산을 일치시킨다. 합성 제안값은 LEAF A 300 W, API 600 W, 예산 1400 W, 사용 3 U, 공간 42 U다. 기존 다른 랙은 유지한다. 합성 출처가 화면과 내보내기에 남아야 한다. 값 누락은 0 또는 통과로 대체하지 않는다.

기본 이름은 API A/B로 바꾸고 ID를 보존하는 안을 권고한다. 이 안은 파일 마이그레이션을 피하지만 기존 데모 화면의 API 01/02 이름이 바뀐다. API 01/02를 유지하는 안은 관련 ID·참조 변경과 저장 호환성 정책이 필요하다. 소유자 결정 전 구현하지 않는다.

## 6. 미정 결정

Q1. 정상 데모의 통과 보류를 보존할지, 합성 NIC PPS 한계를 채워 통과시킬지 결정해야 한다. 권고는 미확인을 보존하고 한계를 채운 별도 테스트 사례에서 정상 통과를 검증하는 것이다. 원문의 정상 통과 인수 기준을 바꾸므로 승인 전 확정하지 않는다.

Q2. API 표시명과 ID 정합 방향을 결정해야 한다. 권고는 기존 ID 보존과 기본 표시명 API A/B다.

## 7. 인수와 제외

서비스 1개, 도메인 3개, 기존 랙 3개를 보존한다. 새 데모·프로젝트 복원·장애 주입·배율 변경 후 판정과 접근명을 검증한다. 기본 도메인 3개의 8개 주입 부분집합과 자원 SPOF 0 전용 사례를 포함한다. 정상 서비스 판정은 Q1 결정에 따른다.

엔진 의미론, 저장 schema, AI, 새 타일, 스윕 배치, 편집 툴바, 의존성 추가는 제외한다. 구현 중 표시 계층만으로 해결할 수 없는 문제가 확인되면 범위를 다시 결정한다.

구체적인 파일과 작업별 완료 기준은 [작업 분할](verdict-delivery-tasks.md)을 따른다.
